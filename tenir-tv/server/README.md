# TENIR TV Cloud

Сервис управления телевизорами TENIR TV: учёт и мониторинг приставок, подключение по коду с экрана,
дизайн главного экрана с предпросмотром, контент (баннеры, новости, ресторан, Wi-Fi) с публикацией версий,
группы номеров, сообщения на экран, удалённые команды. Данные гостей — из Hotel Hub, только на сервере и только
в памяти. ТЗ и обоснование — [../docs/backend.md](../docs/backend.md).

Стек как у Hotel Hub: Python 3.11+, FastAPI, SQLAlchemy 2 (SQLite), Jinja2, Pillow.

## Локальный сервер: требования

Сервис рассчитан на работу **внутри сети отеля** — на отдельном компьютере или мини-ПК. **Hotel Hub стоит на VPS в
интернете**, поэтому сервис сам ходит к нему по HTTPS (только исходящие запросы) и забирает данные по API v1.
Приставкам доступ к хабу не нужен и токена хаба у них нет: они обращаются только к локальному сервису.

```
Exely PMS ──► Hotel Hub (VPS, интернет) ◄── HTTPS, исходящие запросы раз в минуту ── TENIR TV Cloud (сервер в отеле)
                                                                                         ▲   │ HTTP, локальная сеть
                                                                                панель ──┘   ▼
                                                                                    приставки TENIR TV в номерах
```

Входящих подключений из интернета к локальному серверу нет: порт наружу и VPN не нужны, хабу достаточно отвечать на
запросы. Интернет нужен серверу для связи с хабом, а телевизорам — для погоды (Open-Meteo) и Netflix/YouTube.

| | Минимум | Рекомендуется |
|---|---|---|
| Машина | 1 ядро, 1 ГБ ОЗУ, 5 ГБ диска | 2 ядра, 2 ГБ ОЗУ, SSD 20 ГБ (медиатека с фото 4K) |
| ОС | Ubuntu/Debian 22.04+ (установщик `deploy/install.sh`); Windows/macOS — запуск вручную | Ubuntu 24.04 LTS |
| ПО | Python 3.11+ (`python3-venv`); `sqlite3` для резервных копий | — |
| Сеть внутри отеля | сервер и приставки в одной сети или с маршрутизацией между подсетями; порт **8090/TCP** открыт для приставок и рабочих мест администраторов | **постоянный IP** сервера (резерв DHCP в роутере) |
| Выход в интернет (для связи с хабом) | исходящий **HTTPS (443)** до адреса Hotel Hub, DNS; через прокси — переменные `HTTPS_PROXY`/`NO_PROXY` | проводной канал, не Wi-Fi |
| Hotel Hub | адрес на VPS **с HTTPS** (`https://hub.example.com`); токен потребителя с правами `occupancy` и `guests`; отель с этим кодом загружен в хабе | отдельный токен только для этого сервиса |
| Время | NTP включено: без точного времени не проходит проверка TLS-сертификата хаба | — |
| Питание | ИБП: после отключения питания сервис поднимается сам (systemd), приставки продолжают работать на кеше | — |

Запас по нагрузке на сервер: проверено 200 приставок на одном ядре — 97 heartbeat/с при нулевых ошибках, медиана 105 мс
(в жизни ~3,3 запроса/с); память процесса ~110 МБ.

## Связь с Hotel Hub (VPS)

- **Адрес и токен** — в панели «Отели и Hotel Hub». Адрес без схемы (`hub.example.com`) сервис дополняет до
  `https://`. Токен по интернету идёт в заголовке запроса: используйте только **https://** — при `http://` не из
  локальной сети панель предупредит. Редиректы сервис не выполняет (токен не уйдёт на другой адрес) и сообщает об
  этом. Токен хранится на сервере зашифрованным; на приставках его нет.
- **Проверка с сервера одной командой** (печатает только счётчики, без имён гостей):

  ```bash
  HUB_TOKEN='…' tenircloud hubcheck --url https://hub.example.com --code 9305
  # ✓ v1/status → HTTP 200, 120 мс
  # ✓ rooms → 40 номеров, заселено 17, 85 мс (право occupancy есть)
  # ✓ guests → HTTP 200, проживающих в стоянке: 2 (право guests есть), 70 мс
  ```

  Диагностика: токен не принят (401), нет права `occupancy`/`guests` (403), отель не найден (404), хаб недоступен из
  этой сети (интернет, DNS), сертификат не принят. Внутренний корневой сертификат (прокси с перехватом TLS):
  `TENIR_CLOUD_HUB_CA=/путь/ca.pem`.
- **Нагрузка на хаб:** один опрос `rooms` в минуту на отель плюс запросы имён при новом заезде — на порядок меньше
  лимита хаба (120 запросов в минуту на токен), сколько бы ни было приставок.
- **Когда интернет или хаб недоступны:** панель и приставки работают, контент отдаётся с сервера. Опросы
  становятся реже (до ×8), на дашборде видна ошибка. Имена гостей на экранах **скрываются через 10 минут** без
  подтверждения от хаба — персональные данные не показываются устаревшими (`hub.maxAgeMinutes` в контенте, раздел
  JSON; при нестабильном интернете можно увеличить, но выезд гостя тогда дольше остаётся незамеченным). Когда связь
  вернулась, данные обновляются сами.
- **Задержки:** новый заезд или выезд в Exely доходит до экрана за «задержка хаба (webhook + цикл до 20 мин) + до
  минуты опроса + до минуты heartbeat». Сам час выезда (по умолчанию 12:00) приставка применяет локально.

**Безопасность в локальной сети.** Панель и API работают по HTTP: пароль администратора идёт открытым текстом
внутри сети отеля. Не открывайте порт сервиса в интернет. Если нужен доступ извне или шифрование в LAN — поставьте
перед сервисом Caddy/nginx с TLS (внутренний сертификат или домен) и задайте `TENIR_CLOUD_HTTPS=1` и
`TENIR_CLOUD_PUBLIC_URL=https://…`; приставки (Android) принимают и HTTP, и HTTPS. Токен хаба хранится зашифрованным
(`fernet.key` в каталоге данных, права 600), имена гостей в базу не пишутся.

## Установка на сервер

```bash
git clone <репозиторий> && cd iiko-exely-plugin/tenir-tv/server
sudo ./deploy/install.sh install      # служба tenircloud, порт 8090, данные /var/lib/tenircloud
sudo ./deploy/install.sh status       # состояние и /healthz
sudo ./deploy/install.sh backup       # копия в /var/backups/tenircloud (внутри ключи — хранить как пароль)
sudo ./deploy/install.sh update       # после git pull
```

Проверка без изменений в системе: `TENIR_DRY_RUN=1 ./deploy/install.sh install`. Порт меняется `TENIR_PORT=…`.
Если включён ufw: `sudo ufw allow from 192.168.0.0/16 to any port 8090 proto tcp` (подсеть — ваша).

Для разработки и проверки без установки:

```bash
cd tenir-tv/server
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/pytest                                   # 21 тест (+1 с настоящим хабом, если задан)
.venv/bin/tenircloud --data ./data serve           # слушает 0.0.0.0:8090 и печатает адреса в сети
```

Откройте напечатанный адрес → первый вход создаёт администратора → «Отели и Hotel Hub»: код отеля как в хабе
(например `9305`), адрес хаба, токен, «Проверить Hotel Hub и обновить номера».

Переменные окружения:

| Переменная | Значение |
|---|---|
| `TENIR_CLOUD_DATA` | каталог данных: база `cloud.db`, `media/`, ключи `fernet.key`, `session.key` (по умолчанию `./data`) |
| `TENIR_CLOUD_PUBLIC_URL` | адрес, по которому приставки видят сервис (для ссылок на изображения); без него берётся из запроса, то есть тот IP, по которому обратилась приставка |
| `TENIR_CLOUD_HTTPS` | `0` (по умолчанию, локальная сеть по HTTP); `1` — cookie панели только по HTTPS (за прокси с TLS) |
| `TENIR_CLOUD_REGISTER_LIMIT` | регистраций в минуту с одного IP (по умолчанию 10); за NAT, где много ТВ с одним адресом, поднимите |

Сброс пароля: `tenircloud --data ./data passwd admin`. Проверка работы: `curl http://СЕРВЕР:8090/healthz`.

## Готовность к тестам

Автоматические проверки (пройдены 20.10.2026): `pytest` — 21 тест (API приставок, гости и выезд, недоступность хаба,
http/https и сертификат хаба, редиректы, замедление при сбоях, группы, публикация и откат, сообщения, команды, роли и
CSRF, вход по HTTP); **сквозной тест с настоящим Hotel Hub** (`tests/test_real_hub.py`: берётся код хаба из
репозитория `tenirhotels/hotelhub`, база заполняется вымышленными стоянками, сервис получает номера и имена по
API v1, выезд в базе хаба → имя стёрто, ожидаемый заезд без имени, заказчик брони не показывается);
`tools/loadtest.py` — 200 приставок по LAN-адресу, 1000 heartbeat, 0 ошибок; чистая установка `pip install`;
сквозной тест Android-клиента с настоящим сервисом.

Запуск теста с хабом (тестовый хаб, не боевой):

```bash
TENIR_REAL_HUB_URL=http://127.0.0.1:8100 TENIR_REAL_HUB_TOKEN=… TENIR_REAL_HUB_CODE=9305 \
TENIR_REAL_HUB_DB=/путь/к/тестовой/hotelhub.db  pytest tests/test_real_hub.py
```

**Не проверено:** связь с **боевым** хабом на VPS через интернет (в тесте хаб поднят локально по HTTP: TLS,
задержки интернета, прокси не проверялись — для этого `hubcheck`); реальная приставка в вашей сети; установщик
`install.sh` на живой Ubuntu (проверен `bash -n` и пробный режим); Windows/macOS.

План пилота (1–3 номера):

1. Сервер: `install.sh install`, `curl http://СЕРВЕР:8090/healthz` с ноутбука в сети приставок.
2. С сервера: `HUB_TOKEN=… tenircloud hubcheck --url https://hub… --code …` — все три шага ✓.
   Панель: администратор → отель (код как в хабе, адрес `https://…`, токен) → «Проверить Hotel Hub» показывает
   номера и число заселённых → «Контент» → «Опубликовать».
3. Приставка: TENIR TV 0.2.1, в сервисном меню адрес `http://СЕРВЕР:8090`; на экране код; в панели «Приставки» →
   код + номер → через ≤ 1 мин контент отеля и приветствие гостя номера.
4. Проверить по порядку: статус онлайн и данные приставки в карточке (Ethernet, 4K, декодеры); смена дизайна +
   публикация → на ТВ за ≤ 2 мин; сообщение на выбранный номер; команда «Обновить»; выезд гостя в Exely → имя
   пропало; выключить сервер → ТВ работает на кеше, имя скрывается через 10 мин; включить — данные вернулись;
   отключить Hotel Hub → предупреждение на дашборде и общее приветствие на ТВ; перезагрузка приставки → TENIR TV
   сам открылся и снова на связи.
5. Нагрузка (по желанию, на отдельной базе): `python tools/loadtest.py --url http://СЕРВЕР:8090 --login admin
   --password … --devices 200` (создаёт отель LOADTEST и номера L1…LN — удалите после проверки).

## Подключение приставки

1. Установить TENIR TV 0.2.1+, в сервисном меню (на главном экране ↑ ↑ ↓ ↓ ← → ← →, PIN) указать
   «Адрес TENIR TV Cloud» (`http://IP-сервера:8090`) — или `"cloudUrl"` в `device.json`.
2. На экране телевизора появится 6-значный код.
3. Панель → «Приставки» → ввести код, выбрать номер → «Подключить». Через ≤ 1 минуту телевизор покажет контент
   отеля и приветствие гостя номера.

## Устройство

```
tenircloud/
  app.py       сборка приложения, фоновый опрос хаба
  db.py        модели: пользователи, отели, группы, номера, приставки, черновик и версии контента,
               сообщения, команды, медиафайлы, журнал
  tvapi.py     API приставок /api/tv/v1: register, heartbeat, content (ETag), commands/{id}/ack
  hubsync.py   Hotel Hub: rooms + guests, имена только в памяти, выезд, недоступность, отказ токена
  content.py   черновик, публикация, откат, переопределения групп, документ для приставки
  admin.py     панель (роли admin / editor / viewer, журнал, защита от CSRF по Origin)
  media.py     загрузка изображений (до 3840 px), раздача /media
  templates/   страницы панели, preview.html — главный экран 960×540
```

## Что не сделано в этапе 1

- 2FA для входа в панель, обновление APK по воздуху, уведомления о падении приставок — этап 2.
- Отчёты (онлайн по дням, разделы, приложения, занятость, CSV) — этап 3.
- Ограничение частоты heartbeat на приставку (есть только на регистрацию), сравнение версий контента
  (есть предпросмотр любой версии и откат).
- PostgreSQL: схема переносима, но проверялась только на SQLite.
