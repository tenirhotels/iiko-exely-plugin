# TENIR TV Cloud — backend для гостиничных телевизоров

Техническое задание на собственный сервис управления телевизорами TENIR TV: учёт приставок и их состояние,
все настройки, дизайн экрана, контент, данные гостей по заездам из Hotel Hub. Ориентир по возможностям —
LG Pro:Centric Cloud (брошюра 25R3); ориентир по стеку и правилам — Hotel Hub.

Статус: проект, кода сервиса в репозитории нет. Приложение TENIR TV сейчас работает напрямую с Hotel Hub и
статическим `content.json` (см. README), сервис заменит обе связи одной.

## 1. Зачем свой сервис

Сейчас каждой приставке нужны токен Hotel Hub с правом `guests` (доступ ко всем гостям отеля), адрес контента
и ручная настройка номера; состояние приставок не видно, контент правится руками в JSON.

Сервис даёт:

- **Одну точку управления** всеми телевизорами всех отелей сети из браузера.
- **Безопасность гостевых данных:** токен хаба хранится только на сервере; приставка получает имя гостя только
  своего номера и только на время проживания.
- **Подключение приставки за минуту:** установили APK — на экране код — ввели код в панели и выбрали номер.
- **Мониторинг:** онлайн/офлайн, версия приложения, сеть, режим экрана, 4K и декодеры, ошибки.
- **Дизайн и контент без программиста:** редактор с предпросмотром, публикация версий, откат.

## 3. Архитектура

```
 Exely PMS ──► Hotel Hub (API v1, read-only) ──► TENIR TV Cloud ◄──── браузер: панель администратора
                                                   │  SQLite/PostgreSQL, медиафайлы
                                                   ▼
                                  HTTPS: /api/tv/v1 (ключ приставки)
                                                   ▼
                                  приставки TENIR TV в номерах (Android TV Box)
```

- **Стек как у Hotel Hub:** Python 3.11+, FastAPI, SQLAlchemy 2, Jinja2 (панель без SPA), uvicorn,
  `cryptography` (шифрование токена хаба), Pillow (обработка изображений), pytest. Одна команда поддержки на
  оба сервиса, одинаковые развёртывание, резервное копирование и вход с 2FA.
- **База:** SQLite (WAL) для одного–трёх отелей до ~500 приставок; PostgreSQL — при сети отелей.
- **Фоновые задачи** в процессе сервиса: опрос Hotel Hub, пометка офлайн-приставок, чистка устаревших сообщений
  и команд.
- **Медиа:** файлы на диске (`data/media`), раздаются nginx с долгим кешем; имя файла — хеш содержимого.
- **Многоотельность:** все сущности привязаны к отелю (`property`), код отеля = код в Hotel Hub (например 9305).

## 4. Данные

| Сущность | Поля (основные) | Примечание |
|---|---|---|
| Отель | код, название, часовой пояс, адрес хаба, токен хаба (зашифрован), интервал опроса, PIN сервисного меню | токен хаба на приставки не уходит |
| Номер | номер (как в PMS), ID комнаты PMS, группа, статус из хаба (`free`/`booked`/`checked_in`), `stay_id`, плановый выезд, время последнего ответа хаба | список номеров синхронизируется из хаба `rooms`; без хаба — вручную |
| Группа | название, переопределения: приветствие, баннеры, плитки, цвет акцента, язык | у номера одна группа |
| Приставка | uid, хеш ключа, код подключения, отель, номер, имя, язык, последний сеанс, IP, версия приложения, модель, Android, последнее состояние (JSON) | ключ хранится только в виде хеша |
| Черновик контента | JSON (формат `content-format.md`), кто и когда правил | один на отель |
| Версия контента | номер версии, JSON, комментарий, автор, время | публикация = новая версия; откат = публикация старой |
| Сообщение | цель (все / группа / номер / приставка), текст на языках, начало, окончание | показ на главном экране |
| Команда | приставка, вид, создана, доставлена, выполнена, результат | очередь, доставка через heartbeat |
| Медиафайл | файл, исходное имя, размеры, объём | 4K-версия и уменьшенная копия для превью |
| Пользователь | логин, имя, хеш пароля, роль, 2FA, последний вход | роли — см. п. 7 |
| Журнал | время, кто, действие, подробности | все изменения настроек, контента, команд |

**Имена гостей в базу не записываются.** Они живут в памяти процесса: при перезапуске сервиса до следующего
опроса хаба приставки получают «нет подтверждённых данных» и показывают общее приветствие. Так сервис не
становится второй базой гостей (требование ТЗ), а утечка базы не раскрывает проживающих.

## 5. Интеграция с Hotel Hub

Используются существующие маршруты API v1 (подробно — `hotel-hub.md`), токен с правами `occupancy` и `guests`
хранится только на сервере:

1. Раз в `pollSeconds` (по умолчанию 60 с) на каждый отель — `GET /v1/properties/{код}/rooms`: обновить номера,
   статусы, `stay_id`, плановый выезд. Один запрос на отель вместо запроса от каждой приставки — лимит хаба
   (120 запросов в минуту на токен) больше не ограничивает число телевизоров.
2. Для номеров `checked_in` при новой стоянке и раз в 10 опросов — `GET .../stays/{stay_id}/guests`;
   из ответа берутся только имя и фамилия проживающего (`role = "guest"`), телефоны и почта отбрасываются.
3. Выезд (стоянка исчезла или сменилась): имя удаляется из памяти, событие пишется в журнал без имени,
   приставка номера получает новое состояние на ближайшем heartbeat и очищает данные приложений.
4. Хаб недоступен дольше `maxAgeMinutes` (10 мин) — приставкам отдаётся «нет подтверждённых данных»; на
   дашборде предупреждение «Hotel Hub недоступен N минут».
5. Правило часа выезда (12:00 в день выезда) применяется на приставке, как сейчас.

Когда владелец Hotel Hub решит добавить узкий маршрут для ТВ (`hotel-hub.md`, «Чего не хватает»), сервису
хватит права на этот маршрут вместо `guests`.

## 6. API для приставок `/api/tv/v1`

Все ответы JSON, HTTPS. Авторизация — `Authorization: Bearer <ключ приставки>` (кроме регистрации).

| Метод | Назначение |
|---|---|
| `POST /register` | первая регистрация: модель, Android, версия приложения → `device_id`, `device_key` (выдаётся один раз), `pairing_code` (6 цифр, показывается на экране) |
| `POST /heartbeat` | раз в 60 с: состояние приставки (п. 6.1) → привязка, настройки, состояние гостя, версия контента, активные сообщения, новые команды |
| `GET /content` | контент для этой приставки: опубликованная версия + переопределения группы + язык приставки; `ETag`, `304 Not Modified` |
| `POST /commands/{id}/ack` | результат выполнения команды |
| `GET /media/{файл}` | изображения (без авторизации, долгий кеш) |

Ответ heartbeat (пример):

```json
{
  "paired": true,
  "property": {"code": "9305", "name": "TENIR", "timezone": "Asia/Almaty"},
  "room": "305",
  "config": {"language": "", "servicePin": "4826", "pollSeconds": 60},
  "guest": {"status": "checked_in", "stay_id": "S-8f2c", "first_name": "Айгерим", "last_name": "Сапарова",
            "planned_out": "2026-10-22T12:00:00", "confirmed_at": "2026-10-20T09:41:05+05:00"},
  "content": {"version": 14, "etag": "\"c7a1…\""},
  "messages": [{"id": 31, "text": {"ru": "Бассейн закрыт до 14:00", "en": "Pool closed until 14:00"},
                "expires_at": "2026-10-20T14:00:00+05:00"}],
  "commands": [{"id": 902, "kind": "reload_content"}],
  "server_time": "2026-10-20T09:41:10+05:00"
}
```

Не привязанная приставка получает `paired: false`, `pairing_code` и демо-контент; гость — `null`.
`stay_id` — непрозрачный идентификатор стоянки, по его смене приставка понимает, что был выезд.

### 6.1. Состояние приставки (тело heartbeat)

Модель, производитель, Android и API, версия приложения, время работы; сеть (Ethernet/Wi-Fi, сигнал Wi-Fi,
подтверждён ли интернет), IP; экран (текущий режим, поддерживаемые режимы, вывод 4K, HDR); аппаратные декодеры
H.264/HEVC/VP9/AV1 и поддержка 4K; память (всего, свободно), свободное место; TENIR TV — домашний экран по
умолчанию, режим владельца устройства, право автозапуска; версия контента на приставке; текущий экран
(главный, ресторан, внешнее приложение); видимо ли сейчас персональное приветствие (без имени); последние
ошибки (запуск приложений, загрузка контента). Всё это уже собирает `Diagnostics` в приложении.

### 6.2. Команды

| Команда | Действие на приставке | Требования |
|---|---|---|
| `refresh` | обновить контент, гостя, погоду | — |
| `reload_content` | сбросить кеш контента и изображений, загрузить заново | — |
| `clear_apps` | очистить данные приложений из `clearAppsOnCheckout` (выход из Netflix, YouTube) | владелец устройства, Android 9+ |
| `restart_app` | перезапустить TENIR TV | — |
| `reboot` | перезагрузить приставку | владелец устройства |
| `update_app` | скачать и установить новую версию APK | этап 2, владелец устройства |

Команда, не доставленная за 24 часа, помечается просроченной.

## 7. Панель администратора

Роли: **администратор** (всё, включая пользователей, отели и токен хаба), **редактор** (дизайн, контент,
сообщения, команды обновления), **наблюдатель** (просмотр). Вход по паролю, 2FA (TOTP) — как в Hotel Hub.
Все изменения — в журнал.

| Раздел | Что делает |
|---|---|
| Дашборд | по каждому отелю: приставки онлайн/офлайн/ждут подключения, занятость из хаба (заселено/всего), состояние хаба, предупреждения, версии приложения |
| Приставки | таблица: номер, имя, онлайн (последний сеанс), версия, модель, сеть, режим экрана, 4K, предупреждения; фильтры. Карточка: всё состояние, история команд, кнопки команд, привязка к номеру, язык, удаление и перевыпуск ключа |
| Подключение | ввод 6-значного кода с экрана → выбор отеля и номера |
| Номера | номера из хаба: статус, группа, приставки, «проживает» (имя видит только администратор) |
| Группы | создание групп, номера в группе, переопределения: приветствие, баннеры, плитки, акцент, язык |
| Дизайн | логотип, фон, цвет акцента, шрифт заголовков (с засечками / без), затемнение фона, формат имени гостя, показ номера, часы, погода, 24-часовой формат, часовой пояс, интервал баннеров, набор и порядок плиток. **Предпросмотр главного экрана 960×540** с примером гостя: как на телевизоре, обновляется при правке |
| Контент | на трёх языках (ru/en/kk): «Об отеле», Wi-Fi, телефон рецепции; баннеры (картинка, тексты, действие); новости; ресторан (часы, заказ, категории, блюда, цены, фото); приложения (пакеты Netflix/YouTube и свои); погода (координаты). Черновик → «Опубликовать» с комментарием; список версий, сравнение, откат |
| Сообщения | текст на языках, цель (все / группа / номер / приставка), начало и окончание; список активных, досрочное снятие |
| Медиатека | загрузка изображений (JPEG/PNG/WebP), проверка размера (фон от 3840×2160, предупреждение при меньшем), выбор в редакторах |
| Отели и настройки | отели, адрес и токен хаба, «Проверить хаб», интервал опроса, PIN сервисного меню приставок |
| Пользователи, журнал | управление доступом, история изменений |

## 8. Изменения в приложении TENIR TV

1. Новый режим «облако»: в `device.json` и сервисном меню — только адрес сервиса.
2. Регистрация при первом запуске, хранение ключа; пока приставка не привязана — на главном экране крупно
   код подключения и адрес панели.
3. Heartbeat вместо прямого опроса хаба: новый источник `CloudOccupancySource` для существующей `GuestSession`
   (правила показа и очистки при выезде не меняются), контент — из `/content` с ETag.
4. Выполнение команд и подтверждение результата; показ сообщений на главном экране.
5. Отправка состояния (`Diagnostics` в структурированном виде).
6. Прямой режим Hotel Hub и статический `content.json` остаются для работы без сервиса.

## 9. Безопасность

- Токен хаба зашифрован (Fernet), ключ шифрования — файл с правами 600 вне базы.
- Ключ приставки выдаётся один раз, хранится как SHA-256; перевыпуск в панели отключает старый ключ.
- Приставка видит только свой номер; запрос чужих данных невозможен по устройству API.
- Код подключения действует 24 часа и только для не привязанной приставки; после 10 неверных вводов —
  блокировка ввода на 15 минут.
- Панель — только по HTTPS, cookie сессии `HttpOnly`, `Secure`, `SameSite=Lax`, проверка `Origin` для POST.
- Ограничение частоты: heartbeat не чаще раза в 15 с на приставку, регистрация — 10 в минуту с одного IP.
- Резервная копия базы и медиа — ежедневно; имён гостей в копиях нет.

## 10. Развёртывание

- Сервер отеля рядом с Hotel Hub или VPS: 1 vCPU, 1 ГБ ОЗУ, 10 ГБ диска на 200 приставок и медиатеку.
- systemd-служба `tenircloud`, nginx (TLS, раздача `/media`), Let's Encrypt или внутренний сертификат.
- Приставки ходят к сервису по HTTPS; сервис — к Hotel Hub по локальной сети.
- Нагрузка: 200 приставок × 1 heartbeat в минуту ≈ 3,3 запроса в секунду — запас многократный.

## 12. Критерии приёмки MVP

1. Новая приставка показывает код; после ввода кода в панели в течение минуты отображает контент своего отеля
   и приветствие гостя своего номера.
2. На дашборде видно онлайн/офлайн каждой приставки (офлайн — нет heartbeat 3 минуты), версию, сеть, 4K.
3. Изменение дизайна или контента видно в предпросмотре; после публикации — на всех приставках отеля за ≤ 2 минуты;
   откат на прошлую версию работает так же.
4. Группа с другим приветствием и баннерами применяется только к своим номерам.
5. Сообщение появляется на выбранных телевизорах и исчезает по окончании.
6. Команды доставляются и подтверждаются, результат виден в карточке приставки.
7. Выезд в Exely → имя пропадает с экрана номера после синхронизации хаба и ≤ 1 heartbeat; в базе сервиса имён
   нет; при недоступности хаба > 10 минут персональные данные не показываются.
8. Токен хаба отсутствует на приставках; приставка не может получить данные другого номера.
9. Сервис и панель покрыты автотестами (API приставок, правила гостя, публикация, группы, команды, права ролей).

## 13. Почему не karuhun-developer/hotel

Проект изучен (коммит `27b722f`). Подходит как пример админки (Laravel, Livewire, медиатека, меню ресторана,
синхронизация по версиям), но не как основа: имя гостя вводится вручную в карточке номера и не очищается при
выезде, любой ключ API видит всех гостей, нет многоязычия, баннеров, учёта и мониторинга приставок, команд,
предпросмотра; файла лицензии в репозитории нет. Стек (PHP) отличается от Hotel Hub. Полезные идеи —
синхронизация контента по номерам версий и раздел IPTV-каналов — учтены в этапах 1 и 3.
