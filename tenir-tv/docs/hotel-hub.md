# Интеграция TENIR TV с Hotel Hub

Изучен код Hotel Hub (`tenirhotels/hotelhub`, `hotelhub/web/api.py`, `docs/guestconnect-api.md`). Новая база гостей
в телевизоре не создаётся: источник данных о номере, проживании и имени — Hotel Hub (данные Exely PMS).

## Используемые маршруты API v1

Все запросы — `GET`, заголовок `Authorization: Bearer <токен потребителя>`.

| Маршрут | Право токена | Что берёт телевизор |
|---|---|---|
| `/v1/properties/{код}/rooms` | `occupancy` | строка своего номера: `room`, `room_id`, `status` (`free` / `booked` / `checked_in`), `stay_id`, `planned_out` |
| `/v1/properties/{код}/stays/{stay_id}/guests` | `guests` | только `role`, `first_name`, `last_name` проживающего (`role = "guest"`) |

Номер телевизора ищется в `rooms` по `room` (номер на двери, `displayName` PMS) или по `room_id` (ID комнаты в PMS),
без учёта регистра. Имена запрашиваются только для стоянки `checked_in` — при смене стоянки и раз в 10 опросов
(исправление имени в PMS). Для `booked` (ожидается заезд) имена не запрашиваются вовсе.

Маршруты `guestconnect/*` не используются: у них отдельное право и учёт курсора конкретного потребителя
(страница «API» хаба), телевизоры исказили бы эту статистику.

## Правила показа персональных данных

Реализованы в `core/.../guest/GuestSession.kt`, покрыты `GuestSessionTest`:

1. Имя и номер показываются только при подтверждённом проживании: статус `checked_in`, номер найден, ответ хаба
   не старше `hub.maxAgeMinutes` (по умолчанию 10 минут).
2. Хаб недоступен дольше этого срока — показ имени прекращается, экран переходит на общее приветствие
   («Добро пожаловать»). Интерфейс, разделы и приложения продолжают работать.
3. После часа выезда (`hub.checkoutHour`, по умолчанию 12:00 — как в хабе) в день `planned_out` данные скрываются,
   даже если в PMS стоянка ещё не закрыта.
4. Ответ 401/403 (токен отозван, нет права) — данные скрываются сразу.
5. Выезд = стоянка исчезла из номера или сменилась на другую. Тогда данные прежнего гостя стираются из памяти,
   в журнал пишется событие, при настроенном режиме владельца устройства очищаются данные приложений из
   `hub.clearAppsOnCheckout` (например, вход в Netflix/YouTube).
6. На диск имена не пишутся никогда. Сохраняется только `stay_id` последней стоянки — чтобы выезд, случившийся,
   пока приставка была выключена, обработался после включения.
7. Заказчик брони (`role = "customer"`) не показывается: он может не жить в номере (компания, родственник).
   Нет права `guests` — показывается только номер комнаты.

## Где что стоит

Hotel Hub — на VPS в интернете; TENIR TV Cloud и приставки — в локальной сети отеля. Облако отеля ходит к хабу по
HTTPS (исходящие запросы), приставки хаб не видят. Прямой режим «приставка → хаб» (`hubUrl` в `device.json`) требует
интернета на каждом телевизоре и токена в каждом из них — для эксплуатации не рекомендуется. Проверка связи с
сервера отеля — `tenircloud hubcheck` (см. `server/README.md`).

## Токен

Создайте на странице «API» хаба отдельного потребителя «TENIR TV» с правами **`occupancy`** и **`guests`**.

- Право `guests` открывает ФИО, телефоны и e-mail всех гостей отеля: токен хранится в приватных настройках
  приложения (`allowBackup=false`), в сервисном меню виден только хвост из 4 символов. Сервисное меню закрыто PIN.
- Лимит хаба — 120 запросов в минуту на токен. Телевизор делает 1 запрос в `pollSeconds` (60 с) плюс редкие
  запросы имён: на один токен — до ~100 телевизоров. Для большего числа увеличьте `hub.pollSeconds` в контенте
  или выдайте токены группам номеров. При 429 и сетевых ошибках интервал опроса удваивается (до ×8).
- Если хаб доступен только по HTTP в локальной сети, токен идёт открытым текстом — лучше HTTPS.

## Чего не хватает в Hotel Hub (рекомендации, не реализованы)

Hotel Hub меняется только по команде владельца, поэтому ниже — предложение, а не изменения в его коде:

1. **Узкий маршрут для телевизоров**, например `GET /v1/tv/properties/{код}/rooms/{room}` с отдельным правом `tv`:
   `{status, stay_id, first_name, checkout_at}` для одного номера. Тогда токен телевизора не даёт доступа к
   телефонам и почте всех гостей, а `checkout_at` учитывал бы настройку часа выезда хаба.
2. Токен на номер (или привязка токена к номеру) — компрометация одного телевизора не раскрывает другие номера.
3. Отдача контента телевизоров (баннеры, меню) с хаба — сейчас `content.json` берётся по любому HTTPS-адресу.

## Задержки

Хаб получает изменения Exely через webhook и цикл раз в 20 минут. Заселение или выезд в PMS телевизор увидит
через «задержку хаба + до `pollSeconds`». После выезда до обработки хабом имя может оставаться видимым до этого
срока; правило часа выезда (п. 3) скрывает его в стандартный день выезда независимо от хаба.
