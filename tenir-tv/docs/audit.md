# Аудит LauncherCompose и выбор реализации TENIR TV

Проверено: https://github.com/karuhun-developer/LauncherCompose, коммит `7c47e53` («fix padding»), 19.10.2026.

## Что это за проект

Лаунчер для гостиничных Android TV на Jetpack Compose, собранный по шаблону Google «Now in Android»
(build-logic с convention-плагинами, модули `core/*`, `feature/*`, `sync/work`).

| Область | Как сделано |
|---|---|
| Сборка | AGP 8.13.1, Kotlin 2.2.10, compileSdk/targetSdk 35, minSdk 23, KSP, version catalog |
| UI | Compose + `androidx.tv:tv-material` 1.1.0-alpha01, `tv-foundation` 1.0.0-alpha12 |
| Архитектура | MVI-контракты (UiState/UiAction/UiEffect), ViewModel, Hilt, Navigation Compose |
| Данные | Retrofit + kotlinx.serialization, Room, DataStore (proto), Paging 3, WorkManager (синхронизация «change list») |
| Экраны | онбординг, заставка с видео, главный, главное меню, контент, ресторан (категории/блюда), профиль отеля |
| Сервер | собственный backend на Laravel (karuhun-developer/hotel), адрес и токен — в `BuildConfig` |
| Погода | OpenWeatherMap (нужен ключ API в сборке) |
| Запуск приложений | `ApplicationLauncherImpl`: `getLaunchIntentForPackage` + `QUERY_ALL_PACKAGES` |
| Тесты | только шаблонные `ExampleUnitTest` / `ExampleInstrumentedTest` |
| Лицензия | Apache License 2.0 |

## Лицензия и коммерческое использование

Apache 2.0 разрешает коммерческое использование, изменение и распространение, в том числе в закрытом продукте.
Условия: сохранить текст лицензии и уведомления об авторстве в копиях исходного кода, отметить изменённые файлы;
товарные знаки «Karuhun» не использовать. В TENIR TV код LauncherCompose **не скопирован**: заимствованы
решения (категория HOME/LEANBACK_LAUNCHER в манифесте, модель «ресторан → категории → блюда», раздел приложений,
проверка установленного пакета перед запуском). Поэтому обязательств по лицензии в коде TENIR TV не возникает;
если в будущем будут перенесены файлы LauncherCompose, их заголовки с уведомлением Apache 2.0 нужно сохранить.
Иконки Netflix/YouTube из `core/designsystem` в проект не переносились: это товарные знаки, а TENIR TV берёт
баннер и иконку у самого установленного приложения.

## Что выявлено

Сильные стороны: продуманная модульность, офлайн-кеш в Room, синхронизация в фоне, TV-компоненты Compose,
готовая модель меню ресторана, экран заставки.

Проблемы для нашего случая:

1. **Сборка недоступна в закрытом контуре.** Все зависимости — Google Maven (AGP, AndroidX, Compose, Hilt, Firebase-плагины).
   В среде разработки TENIR TV `dl.google.com` закрыт сетевой политикой, поэтому проект не собирается вовсе — ни
   LauncherCompose, ни любой Compose-проект.
2. **Привязка к чужому backend.** Модели и API (`/api/v1/...` Laravel, «change list», комнаты с `guestName`) не совпадают
   с Hotel Hub; почти весь слой данных пришлось бы переписать.
3. **Нет правил для персональных данных.** Имя гостя приходит с сервера и хранится в Room без срока: после выезда
   и при недоступности сервера старое имя остаётся на экране. Это противоречит требованиям ТЗ (п. 4).
4. **Секреты в сборке.** Токен и адрес сервера зашиты в `BuildConfig` (`app.properties`); `google-services.json` в
   репозитории. Для разных номеров/отелей нужна отдельная сборка.
5. **Ошибка в запуске приложений:** в `ApplicationLauncherImpl.launchApplication` результат
   `Resource.Error(ApplicationNotInstalledException())` не возвращается (нет `return`), и код продолжает запуск.
   Кроме того, используется только `getLaunchIntentForPackage`: TV-версии приложений (Netflix `com.netflix.ninja`,
   YouTube `com.google.android.youtube.tv`) обычно объявляют только `LEANBACK_LAUNCHER`, и этот вызов их не находит.
6. **`QUERY_ALL_PACKAGES`** — избыточное право; на Android 11+ хватает `<queries>`.
7. **Нестабильные версии:** `tv-material` alpha, `compose-foundation` alpha; минимум тестов.
8. **Нет масштабирования под 4K** сверх стандартных dp; видеозаставка в 4K на слабых приставках тяжела.
9. **Нет автозапуска после загрузки** (только категория HOME) и нет диагностики приставки.

## Решение для TENIR TV

Взята архитектурная идея LauncherCompose (лаунчер = HOME-активность, разделы как экраны, контент с сервера с
локальным кешем, раздел ресторана, запуск внешних приложений), но реализация новая:

- **Android Views без AndroidX и Compose.** Фреймворк Android есть на любой приставке, APK ~1 МБ, холодный старт
  быстрый даже на Amlogic S905 с 1–2 ГБ ОЗУ, нет alpha-зависимостей. Главное — проект собирается и проверяется в
  текущем контуре (см. «Сборка» в README). Переход на Compose for TV возможен позже поверх того же модуля `core`.
- **Модуль `core` на чистом Kotlin** (без Android): правила показа и очистки данных гостя, разбор контента,
  клиент Hotel Hub, погода — покрыты JVM-тестами.
- **Hotel Hub вместо собственной базы гостей:** используются существующие маршруты API v1 (`rooms`, `guests`),
  имена гостей не пишутся на диск.
- **Настройки телевизора отделены от сборки:** номер комнаты, адрес хаба, токен — через сервисное меню или
  `device.json`; один APK на все номера.
- **Масштаб:** весь интерфейс — холст 960×540 dp, плотность пересчитывается под экран (720p → 213 dpi,
  Full HD → 320, 4K → 640).
- Запуск приложений: `getLeanbackLaunchIntentForPackage` → `getLaunchIntentForPackage`, плитка видна только при
  наличии точки запуска, ошибки показываются гостю и пишутся в журнал.
