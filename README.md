# iiko-exely-plugin

Плагин iikoFront (SDK `Resto.Front.Api.V8`), который связывает кассу ресторана с проживающими гостями отеля из Exely.
Задача: утром на завтраке понять, кто из пришедших живёт в отеле, кому завтрак включён в тариф, и применить
нужную скидку. Работает по образцу интеграции iiko с TravelLine.

Данные Exely плагин берёт **не напрямую**, а из [Hotel Hub](https://github.com/tenirhotels/hotelhub) (`API v1`):
хаб уже ходит в Exely с общим токеном и лимитами, хранит тариф, услуги стоянки (`meal_plan_code`), состав гостей и
лояльность. Касса запрашивает у хаба только список проживающих.

## Возможности

### 1. Электронный реестр завтраков на день
Кнопка **«Реестр завтраков»** (меню плагинов). Для каждого проживающего: комната, фамилии, номер брони, взрослые и дети
отдельно, даты заезда и выезда, сколько завтраков включено (взрослых/детей), сколько выдано, **статус**
(ожидается / использован частично / использован / не использован / отменён / не положен) и **время и источник последнего
изменения** («Exely/хаб» или «iiko: сотрудник») с описанием, что изменилось.

Реестр пересобирается из Hotel Hub при каждом открытии и раз в `refreshSeconds` при работе кассы, сравнивая с прошлым
снимком дня: заметны смена комнаты, число гостей, продление или сокращение проживания, ранний выезд (гость пропал из списка
проживающих до завтрака — «отменён»; поел и уехал — остаётся «использован»). Окно завтрака задают `breakfastStart` и
`breakfastEnd` (по умолчанию 07:00–11:00): после конца окна ожидаемые становятся «не использован». Реестр дня сохраняется
в `registry-ГГГГ-ММ-ДД.json` и `breakfast-registry-ГГГГ-ММ-ДД.csv`.

### 2. Фиксация выданного завтрака
Кнопка **«Проживающий (завтрак)»** на экране заказа: номер комнаты, затем число взрослых и число детей за столом.
- **Право** считается по данным Exely (код питания / услуга «Завтрак» в стоянке или тарифе, день заезда/выезда, `childrenGetBreakfast`).
- **Повторная отметка**: один и тот же заказ дважды отметить нельзя; выданные за день порции вычитаются.
- **Дополнительный гость** сверх нормы — только с подтверждением менеджера (`managerPermissionCode`, окно проверки права iikoFront);
  в журнале: сверх нормы, кто одобрил.
- В журнал пишутся время, сотрудник, номер заказа iiko, взрослые/дети, скидка. В заказ — комментарий и внешние данные `hotel.stay`.
- **Отмена**: реестр → гость → «Отменить отметку». Нужна причина (пустая не принимается) и, при `cancelRequiresManager`, менеджер.
  Запись не удаляется, а помечается отменённой с причиной, временем и автором; порции возвращаются гостю.
- Если завтрака нет в тарифе или порции кончились — скидка проживающего по уровню (лояльность Exely или тариф).

### 3. Прогноз для кухни
Кнопка **«Прогноз завтраков»** (сегодня или завтра): положено взрослых и детей, номеров с завтраком; **ожидаемая явка** =
положенное × средняя доля пришедших за последние `forecastHistoryDays` дней (по реестрам прошлых дней, отдельно взрослые
и дети); **распределение по времени** (слоты по `forecastSlotMinutes`) — по фактическим выдачам из журнала. Пока истории нет,
прогноз равен количеству положенных порций. Завтра учитываются и брони, которые заедут сегодня.
Кнопка **«Кухня: итоги завтрака»**: кухня вводит приготовлено / осталось / списано; в итогах реестра считается процент потерь.

### 4. Заказ по номеру комнаты, рум-сервис
Кнопка **«На номер (рум-сервис)»** на экране заказа, два режима:
- **Рум-сервис**: доставка стоит `roomServiceDeliveryFee` (5000 ₸) и достаётся сотруднику. Гость платит часть по лесенке
  от суммы чека (`roomServiceTiers`), остальное компенсирует отель:

  | Чек, ₸ | Гость платит за доставку | Отель компенсирует |
  |---|---|---|
  | от 40 000 | 0 | 5 000 |
  | от 20 000 | 2 500 | 2 500 |
  | ниже | 5 000 | 0 |

  Доля гостя добавляется в заказ позицией `roomServiceDeliveryProduct` (открытая цена); эту позицию в iikoOffice исключите
  из базы бонусов официантов. Кухня и бар идут в бонусы по обычным правилам заказа. Меню рум-сервиса — отдельная ценовая
  категория `roomServicePriceCategory`; при другой категории плагин предупредит.
- **Допы в ресторане на счёт номера**: сумма заказа относится на номер.

В обоих случаях плагин пишет строку в журнал начислений (`room-charges.json`, CSV за день): номер, гость, чек, доля доставки,
компенсация отеля, курьер, кассир. Кнопка **«Начисления на номер»**: рецепция видит непроведённые строки и отмечает
«проведено» после начисления в Exely. Повторно один заказ на номер отнести нельзя.

## Настройка

### Hotel Hub
Создайте токен потребителя с правами `stays`, `catalog` и (для фамилий в списке) `guests`.
Без `guests` плагин работает, но показывает только номера комнат; без `catalog` тариф определяется только по услугам стоянки.

### iikoOffice
Создайте скидки (ручное применение разрешено) и позицию меню «Доставка рум-сервис» (открытая цена, вне бонусов официантов):
- `Завтрак проживающего` — 100% на группу блюд «Завтрак»;
- `Проживающий` и по одной на каждый уровень (`Проживающий Gold` и т. д.).

Названия должны совпадать с конфигом (регистр не важен).

### Конфиг
При первом запуске плагин создаёт `iiko-exely.json` в папке настроек плагина (`GetConfigsDirectoryPath`). Главное:

```json
{
  "hubUrl": "http://hotelhub.local:8000",
  "propertyCode": "9305",
  "hubToken": "<токен потребителя>",
  "includedBreakfastDiscount": "Завтрак проживающего",
  "defaultResidentDiscount": "Проживающий",
  "residentDiscountRules": [
    { "field": "loyalty",  "contains": "gold",  "discount": "Проживающий Gold" },
    { "field": "ratePlan", "contains": "Люкс",  "discount": "Проживающий Люкс" }
  ]
}
```

Остальные параметры (`breakfastMealPlanCodes`, `breakfastKeywords`, `breakfastOnArrivalDay`, `breakfastOnDepartureDay`,
`childrenGetBreakfast`, `breakfastStart/End`, `managerPermissionCode`, `cancelRequiresManager`, `forecast*`, `roomService*`,
`refreshSeconds`, `orderCommentTemplate`) и их значения по умолчанию — в `PluginConfig.cs`.
`managerPermissionCode` — код права iikoFront, которое подтверждает менеджер; пока он пуст, допуск сверх нормы и отмена
отметок запрещены.
Токен лежит открытым текстом в файле на кассе: ограничьте права на папку и выдавайте токен только с правами чтения.

## Сборка и установка

```
dotnet test  tests/IikoExely.Core.Tests
dotnet publish src/IikoExely.Plugin -c Release -o dist
```

В папку плагинов iikoFront (`...\iiko\iikoRMS\Front.Net\Plugins\Resto.Front.Api.IikoExely\`) копируются
`Resto.Front.Api.IikoExely.dll` и `IikoExely.Core.dll`. Библиотеки `Resto.Front.Api.V8.dll`, `System.Reactive.dll`,
`System.Drawing.Common.dll` iikoFront приносит сам — их копировать не нужно. Версия SDK V8 требует iikoFront
соответствующей версии (см. `GetSupportedApiVersions`).

## Устройство

```
src/IikoExely.Core     без зависимостей от iiko (netstandard2.0): клиент хаба, правила завтрака,
                       выбор скидки, журнал, сверка; покрыто тестами
src/IikoExely.Plugin   тонкая обвязка iikoFront (net472): кнопки, диалоги, скидка через IEditSession
tests/                 xunit (40 тестов)
```

## Не сделано / проверить на живой кассе

- **Проверено только сборкой и тестами ядра.** Плагин не запускался в iikoFront: диалоги, скидка и добавление позиции доставки
  через `IEditSession`, проверка права менеджера — на тестовой кассе.
- **Начисление в Exely не автоматическое.** Хаб только читает Exely, поэтому «на счёт номера» — это журнал для рецепции.
  Оплату в iiko кассир проводит способом оплаты «на номер» (или по вашему процессу) вручную.
- **Лесенка рум-сервиса понята так:** от 40 000 — гость 0, от 20 000 — 2 500, ниже — полная доставка 5 000. Фраза «ниже 5000
  уже сам гость платит» могла означать другой порог для малых чеков (например, минимальный чек); ступени меняются в
  `roomServiceTiers`.
- Курьер = сотрудник, оформивший заказ. Если доставляет другой человек, это пока нужно править в журнале.
- Отмена отметки возвращает порции, но скидку в самом заказе iiko плагин не снимает (заказ может быть уже закрыт).
- Нет отдельного «простого интерфейса» вне iikoFront: всё доступно кнопками на кассе. Для планшета официанта или веб-страницы
  реестра нужен отдельный сервис.
- Статусы и «явка» зависят от того, что кассир отмечает в iiko: гость, поевший без отметки, считается «не использован».
- Идентификатор лицензии `PluginLicenseModuleId(21016318)` — из примеров SDK; для продакшена нужен свой модуль iiko.
- Время кассы считается временем отеля (`DateTime.Now`).
- Номер комнаты вводится цифрами; буквенные номера («A12») потребуют клавиатуры вместо числового диалога.
- Хаб отдаёт стоянки `checked_in` с задержкой синхронизации; сменили комнату или продлили — реестр увидит это после
  очередного цикла хаба (по умолчанию до 20 минут) плюс `refreshSeconds` на кассе.
